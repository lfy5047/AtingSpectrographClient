# AtingSpectrograph 客户端命令接口

控制协议版本：**2**（`kCtrlProtoVersion`）  
UDP 图像流版本：**2**（`kStreamProtoVersion`）

本文档描述 TCP 控制通道的 JSON-RPC 风格命令，以及 UDP 图像流通道的订阅与帧格式，供上位机 / 客户端开发使用。

---

## 1. 连接与端口

| 通道 | 协议 | 默认绑定 | 说明 |
|------|------|----------|------|
| 控制 | TCP | `<ip>:9000` | 命令请求/响应、服务端事件推送 |
| 图像 | UDP | 服务端随机本地端口 | 由服务端向**客户端指定端口**单播发送 |

**单客户端模式**：同一时刻仅允许一条 TCP 连接；新连接会被拒绝。TCP 断开后，UDP 订阅与目标地址自动清空。

**UDP 目标地址**：IP 固定为当前 TCP 对端 IP；端口由 `stream.subscribe` 的 `port` 参数指定。客户端需在本地绑定该端口并接收 UDP。

---

## 2. TCP 控制帧格式

所有多字节整型均为**小端**。如果 `magic` 或 `version` 不匹配，服务端会直接断开 TCP 连接，不返回 JSON 错误帧。

### 2.1 帧头 `CtrlHeader`（16 字节）

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | uint32 | magic | 固定 `0x4E495441`（ASCII `"ATIN"` 小端） |
| 4 | uint16 | version | 控制协议版本，当前为 `2` |
| 6 | uint16 | type | 见 `MsgType` |
| 8 | uint32 | seq | 请求序号（客户端自增）；响应回填同值；事件为 `0` |
| 12 | uint32 | payload_len | 后续 JSON 字节数，最大 1 MiB |

### 2.2 消息类型 `MsgType`

| 值 | 名称 | 方向 | 说明 |
|----|------|------|------|
| 1 | Request | 客户端 → 服务端 | 命令请求 |
| 2 | Response | 服务端 → 客户端 | 命令成功响应 |
| 3 | Event | 服务端 → 客户端 | 异步事件（无需应答） |
| 4 | Error | 服务端 → 客户端 | 命令失败响应 |

### 2.3 请求 JSON（payload）

```json
{
  "cmd": "system.ping",
  "params": {}
}
```

- `cmd`：命令名，点分命名，如 `mirror.set_target`
- `params`：参数对象；无参命令传 `{}`

### 2.4 响应 JSON（payload）

路由层统一包装：

**成功**（`MsgType::Response`）：

```json
{
  "ok": true,
  "data": { }
}
```

**失败**（`MsgType::Error`）：

```json
{
  "ok": false,
  "code": -1,
  "msg": "unknown cmd: foo"
}
```

下文各命令的「返回 `data`」均指成功时 `data` 字段内容；失败时仅有 `code` / `msg`。

### 2.5 事件 JSON（payload）

```json
{
  "evt": "mirror.angle",
  "data": {
    "angle": 12.5,
    "is_moving": false,
    "ts": 1710000000000000000
  }
}
```

| 事件名 | 触发条件 | `data` 字段 |
|--------|----------|-------------|
| `mirror.angle` | 转镜角度查询成功时推送 | `angle` (double), `is_moving` (bool), `ts` (int64, 纳秒) |

## 3. 错误码

| code | 含义 |
|------|------|
| -1 | 未知命令 |
| -2 | 请求 JSON 解析失败 |
| -3 | 参数错误或未知通道名 |
| -10 | 子系统未绑定（如未接转镜/相机） |
| -11 | 设备未就绪或维护操作正在执行 |
| -20 | 转镜串口操作超时 |
| -21 | 红外机芯透传失败 |
| -30 | 无 TCP 连接（如 `stream.subscribe`） |
| -100 | 其它未分类异常 |

## 4. 命令一览

### 4.1 system.* — 系统

#### `system.ping`

心跳 / 时钟探测。

| 参数 | 无 |
|------|-----|
| 返回 `data` | `{ "ts": <int64> }` — 服务端当前时间戳（纳秒） |

#### `system.version`

| 参数 | 无 |
|------|-----|
| 返回 `data` | `{ "version": 2, "name": "AtingSpectrograph" }` |

`version` 表示 TCP 控制协议版本。UDP 图像流版本见本文开头的 `kStreamProtoVersion`。

#### `system.status`

| 参数 | 无 |
|------|-----|
| 返回 `data` | 见下表 |

| 字段 | 类型 | 说明 |
|------|------|------|
| `tcp_connected` | bool | 是否有 TCP 客户端 |
| `udp_target` | bool | 是否已设置 UDP 目标 |
| `channels_mask` | uint32 | 已订阅通道位图 |
| `frames_sent` | uint64 | 已发送帧数 |
| `frames_dropped` | uint64 | 丢弃帧数（队列满或无目标等） |

`channels_mask` 的位号等于通道 ID：`raw16`=bit1、`preview8`=bit2、`slice_stitch16`=bit3、`region_stitch16`=bit4，bit0 当前未使用。

### 4.3 ir.* — 红外机芯

**前置条件**：已 `bindIr`；否则 `code = -10`。

底层为 RS422 机芯协议透传，详细字节含义见 [机芯通信协议.md](./机芯通信协议.md)。

> **兼容性提示**：本节描述当前服务端的语义化 `ir.*` 返回结构。早期服务端可能将命名 `ir.*` 成功返回统一为 `{cmd,data,warning}`；客户端应以实际部署版本文档为准。旧版本服务端不识别新增命令时会返回 `code = -1`（未知命令）。

命名 `ir.*` 命令成功时返回语义化结构：

```json
{
  "value": <typed-value>
}
```

或：

```json
{
  "success": true
}
```

- 读命令返回 `data.value`，值已按命令语义解析。
- 写命令返回 `data.success=true`。
- `ir.save_calib_params` / `ir.maintenance_exec(name="save_calib_params")` 在写入成功但验证读回异常时，可能额外返回 `warning` 字段。
- 仅 `ir.send_raw` 保留原始透传结构。

#### `ir.send_raw`

通用透传（绕过参数校验，谨慎使用）。

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `cmd` | uint8 | 必填 | 命令字 |
| `data` | uint8[] | 必填 | 命令数据；无数据时传 `[]` |
| `readback_len` | uint8 | 必填 | 期望回读长度 |

当前服务端要求上述字段全部显式传入；不要省略 `data` 或 `readback_len`。

成功时返回原始机芯协议数据：

```json
{
  "cmd": <uint8>,
  "data": [<uint8>, ...],
  "warning": ""
}
```

`warning` 为兼容字段，当前固定为空字符串；机芯通信失败返回 `code = -21`。

| 命令 | 参数 | 机芯命令 | 说明 |
|------|------|----------|------|

| `ir.read_self_check` | 无 | `0x21`, 回读 1 字节 | 自检结果字符串，返回 `{"value": string}` |
| `ir.read_focus_plane_temp` | 无 | `0x22`, 回读 2 字节 | 焦平面温度 K，返回 `{"value": double}` |
| `ir.read_mean` | 无 | `0x23`, 回读 2 字节 | 读取均值，返回 `{"value": uint16}` |
| `ir.read_correction_param_gear` | 无 | `0x24`, 回读 1 字节 | 读取校正参数档位，返回 `{"value": uint8}` |
| `ir.read_core_temp` | 无 | `0x25`, 回读 2 字节 | 机芯温度 ℃，返回 `{"value": double}` |
| `ir.read_bad_pixel_count` | 无 | `0x27`, 回读 2 字节 | 读取坏元数量，返回 `{"value": uint16}` |

> 破坏性变更：`ir.read_module_id` 旧版本服务端曾按 8 字节原始数组返回；现按协议修正为 1 字节数值 ID。

`ir.read_self_check` 的 `value` 字符串格式固定为：

```text
D%d T%d F%d M%d CI%d CP%d NC%d TO%d
```

字段依次对应：探测器异常、温度异常、FLASH 状态、DDR 异常、制冷未完成、制冷过程中、不制冷、制冷超时。每个值为 `0` 或 `1`，bit 含义见 [机芯通信协议.md](./机芯通信协议.md)。

#### 维护与校正

**风险提示**：以下命令会修改机芯持久化状态。执行维护命令前必须先调用 `ir.maintenance_unlock(1)` 解锁，或使用 `ir.maintenance_exec` 自动管理解锁/锁定。

| 命令 | 参数 | 机芯命令 | 说明 |
|------|------|----------|------|
| `ir.maintenance_unlock` | `value` uint8 | `0xF0` | 0=锁定, 1=解锁（客户端崩溃后设备保持解锁——优先使用 `ir.maintenance_exec`） |
| `ir.maintenance_exec` | `name` string, `value` uint8 | — | 作用域维护会话：自动解锁→执行→锁定，支持命令见下；无 `value` 动作传 `0` |
| `ir.two_point_calib_p1` | 无 | `0x81`, data=`[0x01]` | 两点校正第一点采集 |
| `ir.two_point_calib_p2` | 无 | `0x82`, data=`[0x01]` | 两点校正第二点采集 |
| `ir.save_calib_params` | 无 | `0x83`, data=`[0x01]` | 校正参数存储（执行后自动验证） |
| `ir.clear_k` | `value` uint8 | `0x94` | k 参数：0=恢复, 1=清除 |
| `ir.clear_b` | `value` uint8 | `0x95` | b 参数：0=恢复, 1=清除 |

`ir.maintenance_exec` 的 `name` 参数可选值：`two_point_calib_p1`、`two_point_calib_p2`、`save_calib_params`、`save_bad_pixel`、`clear_k`、`clear_b`、`bad_pixel_search`。当前服务端要求 `value` 字段显式传入；仅 `clear_k`、`clear_b`、`bad_pixel_search` 会使用该值。

`ir.maintenance_exec` 的结束锁定为 best-effort：服务端会在命令执行后尝试重新锁定维护操作；如果锁定失败，服务端记录日志，客户端可能仍收到本次命令的成功响应。

##### 常见错误码排查

| code | 含义 | 常见原因 |
|------|------|----------|
| -1 | 未知命令 | 服务端版本过旧不支持该命令 |
| -3 | 参数错误 | 参数超出校验范围（如 DDE > 15） |
| -10 | 设备未绑定 | 未调用 `bindIr` |
| -11 | 设备未就绪 | 维护命令已有操作在执行 |
| -21 | 机芯通信失败 | 机芯串口未打开、未响应、通信超时或返回 0xFF 错误帧 |

维护未解锁或机芯返回 `0xFF` 错误帧时，服务端返回 `code = -21`；请调用 `maintenance_unlock(1)` 或使用 `ir.maintenance_exec`。

##### 回退方式

回滚服务端到旧版本即可恢复旧的 raw 返回行为。新增命令被旧服务端视为未知命令，返回 `code = -1`。语义化返回会改变命名 `ir.*` 成功响应结构，客户端升级时需要同步适配。

### 4.6 spectral.* — 光谱投影参数

#### `spectral.get_projection_config`

查询当前光谱投影配置。

| 参数 | 无 |
|------|-----|
| 返回 `data` | 见 `spectral.set_projection_config` |

#### `spectral.set_projection_config`

设置光谱投影配置，并写回本地 `conf.json`。如果当前正在接收 `HeaderFrame` 到 `TailFrame`
之间的数据，服务端会立刻用新参数重算当前已缓存切片并通过内部结果信号输出一张中间结果图；
段结束时仍会再输出最终结果图。二维投影结果只用于本机显示/内部结果通知，不通过 UDP 图像流发送，也不再保存为 tif。

| 参数 | 类型 | 说明 |
|------|------|------|
| `mode` | string | `single_band` / `range_mean` / `rgb` |
| `single_column` | int | `single_band` 模式使用的列号 |
| `range_begin` | int | `range_mean` 模式使用的起始列 |
| `range_end` | int | `range_mean` 模式使用的结束列，服务端按 `[begin, end)` 处理；`0` 表示默认全宽 |
| `rgb_r` / `rgb_g` / `rgb_b` | object | RGB 三通道选择器 |
| `max_frame_count` | uint64 | 一段最多累积多少列，`0` 表示使用默认值 |

`rgb_*` 选择器字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `use_range` | bool | `false` 表示单列，`true` 表示范围均值 |
| `single_column` | int | `use_range=false` 时使用 |
| `range_begin` | int | `use_range=true` 时使用 |
| `range_end` | int | `use_range=true` 时使用，按 `[begin, end)` 处理；`0` 表示默认全宽 |

返回 `data`：当前生效的完整配置，并包含 `emit_status`：

| `emit_status` | 说明 |
|------|------|
| `emitted` | 当前段已有缓存切片，已立即输出一张中间结果图 |
| `pending_next_slice` | 当前还没有可用切片，下一片有效切片到来后会自动输出 |
| `config_saved_no_active_segment` | 配置已保存，但当前没有活动段，不触发立即输出 |

示例：

```json
{
  "cmd": "spectral.set_projection_config",
  "params": {
    "mode": "range_mean",
    "single_column": 0,
    "range_begin": 0,
    "range_end": 0,
    "rgb_r": { "use_range": false, "single_column": 0, "range_begin": 0, "range_end": 0 },
    "rgb_g": { "use_range": false, "single_column": 0, "range_begin": 0, "range_end": 0 },
    "rgb_b": { "use_range": false, "single_column": 0, "range_begin": 0, "range_end": 0 },
    "max_frame_count": 1008
  }
}
```

#### 光谱三维数据保存

`SpectralProjectionAlgo` 在每段 Tail 或 `max_frame_count` 上限 flush 时保存一份三维 tif。
保存内容与当前投影模式无关，始终包含所有 wavelength columns。

文件格式为未压缩 16bit 多页灰度 TIFF：

| 字段 | 说明 |
|------|------|
| page 轴 | wavelength/x，每个波段列一页 |
| 每页 Mat 尺寸 | `(slice_height, frame_count)`，即 rows 为高度、cols 为帧序号 |
| TIFF 尺寸 | `IMAGEWIDTH=frame_count`，`IMAGELENGTH=slice_height` |
| 像素含义 | 第 `x` 页 `(y, frame_index)` = 第 `frame_index` 个切片的 `(y, x)` |
| 元数据 | `TIFFTAG_IMAGEDESCRIPTION` 和 `TIFFTAG_DOCUMENTNAME` 均写入同一份 JSON |

## 5. UDP 图像流格式

所有多字节整型均为**小端**。UDP 使用统一的 64 字节 `StreamHeader`，所有通道都按同一结构解析。

### 5.1 帧头 `StreamHeader`（64 字节）

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | uint32 | magic | `0x4D545341`（`"ASTM"` 小端） |
| 4 | uint8 | version | `2` |
| 5 | uint8 | channel | 通道 ID（1~4） |
| 6 | uint16 | flags | bit0=`LastFragment` 表示该帧最后一个分片 |
| 8 | uint64 | frame_id | 单调递增帧 ID |
| 16 | uint16 | pkt_index | 分片序号，从 0 起 |
| 18 | uint16 | pkt_total | 分片总数 |
| 20 | uint32 | frame_bytes | 整帧 payload 总字节数 |
| 24 | uint16 | width | 图像宽 |
| 26 | uint16 | height | 图像高 |
| 28 | uint16 | pixel_format | `1`=Mono8, `2`=Mono16 |
| 30 | uint16 | meta_flags | bit0=`HasRawFrameMeta` |
| 32 | int64 | timestamp_ns | RawFrame 时间戳 |
| 40 | int64 | mirror_timestamp_ns | 转镜角度时间戳 |
| 48 | uint64 | mirror_angle_bits | 转镜角度的 IEEE754 `double` 位模式 |
| 56 | uint8 | frame_type | `0`=Unknown, `1`=Header, `2`=Data, `3`=Tail |
| 57 | uint8 | is_latest_mirror_frame | `0`/`1` |
| 58 | uint16 | reserved0 | 保留 |
| 60 | uint32 | reserved1 | 保留 |

帧后紧跟本包 payload，长度为 `min(udp_payload, frame_bytes - pkt_index * udp_payload)`。

`raw16` 与 `preview8` 会携带源 `RawFrame` 元数据，`meta_flags & 0x1` 置位。`slice_stitch16` 在存在源 `RawFrame` 时携带元数据；没有源帧时 `meta_flags` 不置位，元数据字段为 0。`region_stitch16` 当前默认流程未主动推送，若后续接入推送且没有源帧元数据，也应按 `meta_flags == 0` 处理。

### 5.2 客户端组帧

1. 按 `frame_id` + `channel` 归类分片。
2. 校验 `pkt_total` 与收到的 `pkt_index` 集合完整。
3. 按 `pkt_index` 顺序拼接 payload，总长度应等于 `frame_bytes`。
4. 若 `meta_flags & 0x1`，可读取 `timestamp_ns/mirror_* /frame_type` 元数据；否则按 0 处理。
5. Mono16：像素为 `width * height` 个 uint16 小端；Mono8 同理为 uint8。

UDP 不保证顺序和到达。客户端应允许 `frame_id` 跳号，并为未收齐的分片设置超时清理策略。

### 5.3 像素布局

- **Mono16**：每像素 2 字节，行优先，小端 uint16。
- **Mono8**（`preview8`）：每像素 1 字节，行优先。
- **mirror_angle_bits**：客户端将 `uint64` 按 IEEE754 重解释为 `double`，得到角度值。

## 6. 推荐调用流程

```
1. TCP 连接服务端 control_port（默认 9000）
2. system.version / system.ping 校验协议
3. 本地 UDP bind(port)，调用 stream.subscribe { port, channels: ["raw16"] }
4. camera.start_stream（若需相机原始流）
5. 循环接收 UDP，按 StreamHeader 组帧
6. 可选：处理 TCP Event mirror.angle
7. 断开前 stream.unsubscribe { "all": true }，camera.stop_stream
```
