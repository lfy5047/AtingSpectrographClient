# AtingSpectrograph 客户端命令接口

控制协议版本：**2**（`kCtrlProtoVersion`）  
UDP 图像流版本：**3**（`kStreamProtoVersion`）

本文档描述 TCP 控制通道的 JSON-RPC 风格命令，以及 UDP 图像流通道的订阅与帧格式，供上位机 / 客户端开发使用。

---

## 1. 连接与端口

| 通道 | 协议 | 默认绑定 | 说明 |
|------|------|----------|------|
| 控制 | TCP | `<ip>:9000` | 命令请求/响应、服务端事件推送 |
| 图像 | UDP | 服务端随机本地端口 | 由服务端向**客户端指定端口**单播发送 |

**单客户端模式**：同一时刻仅允许一条 TCP 连接；新连接会被拒绝。TCP 断开后，UDP 订阅与目标地址自动清空。

**UDP 目标地址**：IP 固定为当前 TCP 对端 IP；端口由 `stream.subscribe` 的 `port` 参数指定。客户端需在本地绑定该端口并接收 UDP。

---

## 2. TCP 控制帧格式

所有多字节整型均为**小端**。如果 `magic` 或 `version` 不匹配，服务端会直接断开 TCP 连接，不返回 JSON 错误帧。

### 2.1 帧头 `CtrlHeader`（16 字节）

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | uint32 | magic | 固定 `0x4E495441`（ASCII `"ATIN"` 小端） |
| 4 | uint16 | version | 控制协议版本，当前为 `2` |
| 6 | uint16 | type | 见 `MsgType` |
| 8 | uint32 | seq | 请求序号（客户端自增）；响应回填同值；事件为 `0` |
| 12 | uint32 | payload_len | 后续 JSON 字节数，最大 1 MiB |

### 2.2 消息类型 `MsgType`

| 值 | 名称 | 方向 | 说明 |
|----|------|------|------|
| 1 | Request | 客户端 → 服务端 | 命令请求 |
| 2 | Response | 服务端 → 客户端 | 命令成功响应 |
| 3 | Event | 服务端 → 客户端 | 异步事件（无需应答） |
| 4 | Error | 服务端 → 客户端 | 命令失败响应 |

### 2.3 请求 JSON（payload）

```json
{
  "cmd": "system.ping",
  "params": {}
}
```

- `cmd`：命令名，点分命名，如 `mirror.set_target`
- `params`：参数对象；无参命令传 `{}`

### 2.4 响应 JSON（payload）

路由层统一包装：

**成功**（`MsgType::Response`）：

```json
{
  "ok": true,
  "data": { }
}
```

**失败**（`MsgType::Error`）：

```json
{
  "ok": false,
  "code": -1,
  "msg": "unknown cmd: foo"
}
```

下文各命令的「返回 `data`」均指成功时 `data` 字段内容；失败时仅有 `code` / `msg`。

### 2.5 事件 JSON（payload）

```json
{
  "evt": "mirror.angle",
  "data": {
    "angle": 12.5,
    "is_moving": false,
    "ts": 1710000000000000000
  }
}
```

| 事件名 | 触发条件 | `data` 字段 |
|--------|----------|-------------|
| `mirror.angle` | 转镜角度查询成功时推送 | `angle` (double), `is_moving` (bool), `ts` (int64, 纳秒) |

---

## 3. 错误码

| code | 含义 |
|------|------|
| -1 | 未知命令 |
| -2 | 请求 JSON 解析失败 |
| -3 | 参数错误或未知通道名 |
| -10 | 子系统未绑定（如未接转镜/相机） |
| -11 | 设备未就绪或维护操作正在执行 |
| -20 | 转镜串口操作超时 |
| -21 | 红外机芯透传失败 |
| -22 | 温控仪通信失败 |
| -30 | 无 TCP 连接（如 `stream.subscribe`） |
| -100 | 其它未分类异常 |

## 4. 命令一览

### 4.1 system.* — 系统

#### `system.ping`

心跳 / 时钟探测。

| 参数 | 无 |
|------|-----|
| 返回 `data` | `{ "ts": <int64> }` — 服务端当前时间戳（纳秒） |

#### `system.version`

| 参数 | 无 |
|------|-----|
| 返回 `data` | `{ "version": 2, "name": "AtingSpectrograph" }` |

`version` 表示 TCP 控制协议版本。UDP 图像流版本见本文开头的 `kStreamProtoVersion`。

#### `system.status`

| 参数 | 无 |
|------|-----|
| 返回 `data` | 见下表 |

| 字段 | 类型 | 说明 |
|------|------|------|
| `tcp_connected` | bool | 是否有 TCP 客户端 |
| `udp_target` | bool | 是否已设置 UDP 目标 |
| `channels_mask` | uint32 | 已订阅通道位图 |
| `frames_sent` | uint64 | 已发送帧数 |
| `frames_dropped` | uint64 | 丢弃帧数（队列满或无目标等） |

`channels_mask` 的位号等于通道 ID：`raw16`=bit1、`preview8`=bit2、`slice_stitch16`=bit3、`region_stitch16`=bit4、`spectral_preview`=bit5，bit0 当前未使用。

### 4.3 ir.* — 红外机芯

> **破坏性变更**：旧版红外一级命名已移除。旧机芯命令统一使用 `ir.legacy.*`，CI05 命令统一使用 `ir.ci05.*`。

客户端迁移和接入流程见 [红外机芯客户端开发文档.md](./红外机芯客户端开发文档.md)。本节保留完整命令参考。

**前置条件**：legacy 命令已 `bindLegacyIr`，CI05 命令已 `bindCi05Ir`；未绑定时 `code = -10`。

legacy 底层为 RS422 旧机芯协议透传，详细字节含义见 [机芯通信协议.md](./机芯通信协议.md)。CI05 底层为 `55 AA ... F0` 独立协议。

#### `ir.core.current`

查询服务启动时从配置文件选择的当前机芯类型。该值为静态配置结果；切换机芯需要修改配置并重启服务。

请求：

```json
{"cmd":"ir.core.current","params":{}}
```

响应：

```json
{"ok":true,"data":{"model":"legacy"}}
```

或：

```json
{"ok":true,"data":{"model":"ci05"}}
```

#### Legacy 命令：`ir.legacy.*`

> **兼容性提示**：本节描述当前服务端的语义化 legacy 返回结构。早期服务端可能将命名 `ir.*` 成功返回统一为 `{cmd,data,warning}`；客户端应以实际部署版本文档为准。旧版本服务端不识别新增命令时会返回 `code = -1`（未知命令）。

命名 `ir.legacy.*` 命令成功时返回语义化结构：

```json
{
  "value": <typed-value>
}
```

或：

```json
{
  "success": true
}
```

- 读命令返回 `data.value`，值已按命令语义解析。
- 写命令返回 `data.success=true`。
- `ir.legacy.save_calib_params` / `ir.legacy.maintenance_exec(name="save_calib_params")` 在写入成功但验证读回异常时，可能额外返回 `warning` 字段。
- 仅 `ir.legacy.send_raw` 保留原始透传结构。

#### `ir.legacy.send_raw`

通用透传（绕过参数校验，谨慎使用）。

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `cmd` | uint8 | 必填 | 命令字 |
| `data` | uint8[] | 必填 | 命令数据；无数据时传 `[]` |
| `readback_len` | uint8 | 必填 | 期望回读长度 |

当前服务端要求上述字段全部显式传入；不要省略 `data` 或 `readback_len`。

成功时返回原始机芯协议数据：

```json
{
  "cmd": <uint8>,
  "data": [<uint8>, ...],
  "warning": ""
}
```

`warning` 为兼容字段，当前固定为空字符串；机芯通信失败返回 `code = -21`。

#### 维护与校正

**风险提示**：以下命令会修改机芯持久化状态。执行维护命令前必须先调用 `ir.legacy.maintenance_unlock(1)` 解锁，或使用 `ir.legacy.maintenance_exec` 自动管理解锁/锁定。

| 命令 | 参数 | 机芯命令 | 说明 |
|------|------|----------|------|
| `ir.legacy.maintenance_unlock` | `value` uint8 | `0xF0` | 0=锁定, 1=解锁（客户端崩溃后设备保持解锁——优先使用 `ir.legacy.maintenance_exec`） |
| `ir.legacy.maintenance_exec` | `name` string, `value` uint8 | — | 作用域维护会话：自动解锁→执行→锁定，支持命令见下；无 `value` 动作传 `0` |
| `ir.legacy.two_point_calib_p1` | 无 | `0x81`, data=`[0x01]` | 两点校正第一点采集 |
| `ir.legacy.two_point_calib_p2` | 无 | `0x82`, data=`[0x01]` | 两点校正第二点采集 |
| `ir.legacy.save_calib_params` | 无 | `0x83`, data=`[0x01]` | 校正参数存储（执行后自动验证） |
| `ir.legacy.clear_k` | `value` uint8 | `0x94` | k 参数：0=恢复, 1=清除 |
| `ir.legacy.clear_b` | `value` uint8 | `0x95` | b 参数：0=恢复, 1=清除 |

`ir.legacy.maintenance_exec` 的 `name` 参数可选值：`two_point_calib_p1`、`two_point_calib_p2`、`save_calib_params`、`save_bad_pixel`、`clear_k`、`clear_b`、`bad_pixel_search`。当前服务端要求 `value` 字段显式传入；仅 `clear_k`、`clear_b`、`bad_pixel_search` 会使用该值。

`ir.legacy.maintenance_exec` 的结束锁定为 best-effort：服务端会在命令执行后尝试重新锁定维护操作；如果锁定失败，服务端记录日志，客户端可能仍收到本次命令的成功响应。

#### CI05 命令：`ir.ci05.*`

CI05 使用独立的 `55 AA DATA1 DATA2 DATA3 DATA4 XOR F0` 控制帧和 `55 BB ... F0` 反馈帧，不复用 legacy 的 `5E 5E ... E5 E5` 协议。

CI05 说明书没有统一 ACK。除查询命令外，`ir.ci05.*` 写命令成功仅表示服务端已按 `55 AA DATA1 DATA2 DATA3 DATA4 XOR F0` 完整写入串口；若需要确认机芯状态，请再调用对应 `read_status*` 或查询命令。

连续调焦/变倍命令必须配合 `ir.ci05.focus_stop` 或 `ir.ci05.zoom_stop`。客户端退出、超时或切换控制对象前必须发送停止命令。

危险命令：`ir.ci05.serial_passthrough_enable`、CI05 NUC 命令组、CI05 坏元命令组、`ir.ci05.set_detector_power` 会改变机芯内部状态、校正参数、坏元列表或供电状态。普通自动流程不得调用这些命令。

| 命令 | 参数 | CI05 四字节 | 响应/说明 |
|------|------|-------------|-----------|
| `ir.ci05.send_raw` | `data1,data2,data3,data4,expected_type,timeout_ms` | `DATA1 DATA2 DATA3 DATA4` | 原始命令透传，返回 `{"type": uint8, "data": uint8[5]}` |

| `ir.ci05.focus_start_negative` | 无 | `01 02 00 00` | 连续负向调焦 |
| `ir.ci05.focus_stop` | 无 | `01 03 00 00` | 调焦停止，可重复调用 |
| `ir.ci05.focus_step_positive` | 无 | `01 24 00 00` | 单步正向调焦 |
| `ir.ci05.focus_step_negative` | 无 | `01 25 00 00` | 单步负向调焦 |
| `ir.ci05.zoom_start_positive` | 无 | `01 04 00 00` | 连续正向变倍 |

##### 常见错误码排查

| code | 含义 | 常见原因 |
|------|------|----------|
| -1 | 未知命令 | 服务端版本过旧不支持该命令 |
| -3 | 参数错误 | 参数超出校验范围（如 DDE > 15） |
| -10 | 设备未绑定 | 未调用 `bindLegacyIr` 或 `bindCi05Ir` |
| -11 | 设备未就绪 | 维护命令已有操作在执行 |
| -21 | 机芯通信失败 | 机芯串口未打开、未响应、通信超时或返回 0xFF 错误帧 |

维护未解锁或机芯返回 `0xFF` 错误帧时，服务端返回 `code = -21`；请调用 `ir.legacy.maintenance_unlock(1)` 或使用 `ir.legacy.maintenance_exec`。

##### 回退方式

回滚服务端到旧版本即可恢复旧的 raw 返回行为。新增命令被旧服务端视为未知命令，返回 `code = -1`。本次拆分移除了旧一级 `ir.*` 命名，客户端升级时需要同步适配到 `ir.legacy.*` 或 `ir.ci05.*`。

### 4.4 tempctrl.* — 温控仪

**前置条件**：`conf.json` 中 `temperature_controller.enabled=true` 且服务端已成功初始化温控仪串口；否则 `code=-10` 或 `code=-11`。

底层为温控仪 ASCII 串口协议，详细参数名和错误码见 [温控仪通信协议.md](./温控仪通信协议.md)。服务端内部按参数表映射协议中的 57 个 key；也可以通过 `module + param` 直接访问。

```json
"temperature_controller": {
  "enabled": true,
  "default_module": "TC1",
  "serial_port": {
    "port": "/dev/ttyUSB2",
    "baud": 9600,
    "data_bits": 8,
    "stop_bits": 1,
    "parity": 0
  },
  "timeout_ms": 1000,
  "min_send_interval_ms": 60
}
```

#### 采集超采样配置

客户端侧看到的 `slice_stitch_algo.stitch_count`、UDP 图像宽度、Raw 段输出帧数和 Header/Data/Tail 语义保持不变。`oversample_factor=1` 表示关闭超采样，行为与旧版本一致。

#### `collect.get_oversampling`

| 参数 | 无 |
|------|-----|

#### `collect.set_oversampling`

| 参数 | 类型 | 说明 |
|------|------|------|
| `oversample_factor` | int | 超采样倍率，必须 `>= 1`；`1` 表示关闭超采样 |

| 返回 `data` | `{ "oversample_factor": <int>, "effective_s_speed": <int>, "effective_f_speed": <int>, "is_collecting": false }` |
|-------------|------------------------------------------------------------------------------------------|

设置成功后会写回 `conf.json`，并刷新后续采集段使用的转镜速度和采集窗口估算。采集中不允许修改，服务端返回 `code = -12`；参数小于 1 返回 `code = -3`。

#### 文件 TCP 传输格式

客户端连接 `file_port` 后，先发送：

| 字段 | 类型 | 说明 |
|------|------|------|
| `json_len` | uint32 | 小端 JSON 长度 |
| `json` | bytes | `{"transfer_id":"..."}` |

验证成功后服务端连续发送 `FileChunkHeader + filename + payload`。`transfer_id` 为一次性令牌，
默认 30 秒内有效，验证后立即失效；超时或重复使用会失败并断开连接。

`FileChunkHeader` 为 44 字节，小端：

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | uint32 | magic | `0x44465441`（`"ATFD"` 小端） |
| 4 | uint16 | version | `1` |
| 6 | uint16 | flags | bit0=`LastChunk`，bit1=`LastFile` |
| 8 | uint32 | file_index | 当前文件序号 |
| 12 | uint32 | file_count | 文件总数 |
| 16 | uint64 | offset | 当前 payload 在文件内的偏移 |
| 24 | uint64 | file_size | 当前文件总字节数 |
| 32 | uint32 | filename_len | 文件名长度 |
| 36 | uint32 | payload_len | payload 长度 |
| 40 | uint32 | reserved | 保留 |

客户端按 `filename_len` 读取文件名，再读取 `payload_len` 字节 payload。收到 `LastFile`
标志后，本次传输完成，服务端会关闭文件连接。v1 不支持断点续传；传输失败后重新调用
`record.fetch`。

## 5. UDP 图像流格式

所有多字节整型均为**小端**。UDP 使用统一的 64 字节 `StreamHeader`，所有通道都按同一结构解析。

### 5.1 帧头 `StreamHeader`（64 字节）

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | uint32 | magic | `0x4D545341`（`"ASTM"` 小端） |
| 4 | uint8 | version | `3` |
| 5 | uint8 | channel | 通道 ID（1~5） |
| 6 | uint16 | flags | bit0=`LastFragment` 表示该帧最后一个分片 |
| 8 | uint64 | frame_id | 单调递增帧 ID |
| 16 | uint16 | pkt_index | 分片序号，从 0 起 |
| 18 | uint16 | pkt_total | 分片总数 |
| 20 | uint32 | frame_bytes | 整帧 payload 总字节数 |
| 24 | uint16 | width | 图像宽 |
| 26 | uint16 | height | 图像高 |
| 28 | uint16 | pixel_format | `1`=Mono8, `2`=Mono16, `3`=Jpeg |
| 30 | uint16 | meta_flags | bit0=`HasRawFrameMeta`，bit1=`HasScanDirection` |
| 32 | int64 | timestamp_ns | RawFrame 时间戳 |
| 40 | int64 | mirror_timestamp_ns | 转镜角度时间戳 |
| 48 | uint64 | mirror_angle_bits | 转镜角度的 IEEE754 `double` 位模式 |
| 56 | uint8 | frame_type | `0`=Unknown, `1`=Header, `2`=Data, `3`=Tail |
| 57 | uint8 | is_latest_mirror_frame | `0`/`1` |
| 58 | uint8 | reverse_scan | `0`=正向/未知，`1`=反向；仅 `meta_flags & 0x2` 时有效 |
| 59 | uint8 | reserved0 | 保留 |
| 60 | uint32 | reserved1 | 保留 |

帧后紧跟本包 payload，长度为 `min(udp_payload, frame_bytes - pkt_index * udp_payload)`。

Stream v3 保持 64 字节头长度和既有字段偏移兼容；严格校验 `version == 2` 的旧客户端需要适配 v3 后才能接收新增字段。

`raw16` 与 `preview8` 会携带源 `RawFrame` 元数据，`meta_flags & 0x1` 置位，但它们在进采集门控前推送，不承诺扫描方向，`meta_flags & 0x2` 不置位。`slice_stitch16` 在存在源 `RawFrame` 时携带元数据；当源帧来自门控采集段或文件 metadata 且方向可信时，同时置 `meta_flags & 0x2` 并填充 `reverse_scan`。没有源帧或方向未知时不置方向位，方向字段按 0 处理。`region_stitch16` 当前默认流程未主动推送，若后续接入推送且没有源帧元数据，也应按 `meta_flags == 0` 处理。`spectral_preview` 复用 SpectralProjection 结果对应源 `RawFrame` 的元数据；图像已在服务端按扫描方向校正，客户端不应按 `reverse_scan` 再次翻转。

### 5.2 客户端组帧

1. 按 `frame_id` + `channel` 归类分片。
2. 校验 `pkt_total` 与收到的 `pkt_index` 集合完整。
3. 按 `pkt_index` 顺序拼接 payload，总长度应等于 `frame_bytes`。
4. 若 `meta_flags & 0x1`，可读取 `timestamp_ns/mirror_* /frame_type` 元数据；否则按 0 处理。
5. 若 `meta_flags & 0x2`，可读取 `reverse_scan`；否则扫描方向未知。
6. 当 `pixel_format == 1/2` 时按裸像素解析：Mono16 为 `width * height` 个 uint16 小端，Mono8 同理为 uint8。
7. 当 `pixel_format == 3` 时，payload 是一张完整 JPEG 图片；客户端必须先组齐所有分片，再把完整 payload 交给 JPEG 解码器。

UDP 不保证顺序和到达。客户端应允许 `frame_id` 跳号，并为未收齐的分片设置超时清理策略。

### 5.3 像素布局

- **Mono16**：每像素 2 字节，行优先，小端 uint16。
- **Mono8**（`preview8`）：每像素 1 字节，行优先。
- **Jpeg**（`spectral_preview`）：payload 为完整 JPEG 文件字节流，`frame_bytes` 为 JPEG 字节数，`width`/`height` 表示解码后图像尺寸；该通道仅用于显示预览，不保留 16bit 光谱强度。
- **mirror_angle_bits**：客户端将 `uint64` 按 IEEE754 重解释为 `double`，得到角度值。
- **reverse_scan**：`1` 表示该帧来源于反向扫描段。对服务端已校正方向的 `SpectralProjection`/保存结果，客户端只展示或记录该标志，不应再次翻转图像。

## 6. 推荐调用流程

```
1. TCP 连接服务端 control_port（默认 9000）
2. system.version / system.ping 校验协议
3. 本地 UDP bind(port)，调用 stream.subscribe { port, channels: ["raw16"] }
4. camera.start_stream（若需相机原始流）
5. 循环接收 UDP，按 StreamHeader 组帧
6. 可选：处理 TCP Event mirror.angle
7. 断开前 stream.unsubscribe { "all": true }，camera.stop_stream
```

## 7. 请求示例

**发送**（`seq=1`，type=Request）：

```json
{"cmd":"mirror.query_angle","params":{}}
```

**成功响应**（`seq=1`，type=Response）：

```json
{"ok":true,"data":{"angle":175.0,"is_moving":false}}
```

**失败响应**（type=Error）：

```json
{"ok":false,"code":-10,"msg":"mirror not bound"}
```

**订阅图像流**：

```json
{"cmd":"stream.subscribe","params":{"port":9100,"channels":["raw16","preview8","spectral_preview"]}}
```
