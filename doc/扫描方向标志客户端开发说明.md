# 扫描方向标志客户端开发说明

本文说明客户端如何适配 UDP Stream v3 中新增的 `reverse_scan` 扫描方向标志，以及如何理解服务端对反向扫描图像的校正行为。

## 适配范围

- UDP 图像流协议版本从 `2` 升级为 `3`，`StreamHeader` 仍为 64 字节。
- `StreamHeader` 偏移 58 新增 `uint8 reverse_scan`，偏移 59 为 `uint8 reserved0`，偏移 60 的 `reserved1` 不变。
- `meta_flags` 新增 bit1：`HasScanDirection = 0x2`。
- 严格校验 `version == 2` 的旧客户端需要改为接受 `version == 3`。

## 字段含义

客户端只有在 `meta_flags & 0x2` 非零时，才可以读取 `reverse_scan`。

| 字段 | 含义 |
|------|------|
| `meta_flags & 0x2 == 0` | 扫描方向未知，不要使用 `reverse_scan` |
| `meta_flags & 0x2 != 0 && reverse_scan == 0` | 可信正向扫描 |
| `meta_flags & 0x2 != 0 && reverse_scan == 1` | 可信反向扫描 |

`reverse_scan=false` 本身不能表示“可信正向”，必须同时检查 `HasScanDirection`。

## 各通道行为

| 通道 | 是否承诺方向 | 客户端处理 |
|------|--------------|------------|
| `raw16` | 不承诺 | 仍按实时相机帧处理；忽略 `reverse_scan` |
| `preview8` | 不承诺 | 仍按实时预览帧处理；忽略 `reverse_scan` |
| `slice_stitch16` | 有源帧且方向可信时承诺 | 先判断 `meta_flags & 0x2`，再读取 `reverse_scan` |
| `region_stitch16` | 当前默认流程不承诺 | 未置方向 bit 时按未知处理 |

`raw16` 和 `preview8` 在进入采集门控前推送，所以它们不携带可信扫描方向。`slice_stitch16` 来自门控采集段或带 metadata 的文件回放时，才会携带可信方向。

## 图像翻转规则

服务端已经在 `SpectralProjection` 算法层修正反向扫描方向：

- 实时 `SpectralProjection` 二维图：反向段已水平翻转为正向显示。
- 保存的光谱投影 TIFF：反向段的 frame 轴已按扫描方向倒序，metadata 写入 `frame_axis_order: "scan_corrected"`。

因此客户端不要因为 `reverse_scan == 1` 再次翻转已校正的 `SpectralProjection` 图像或保存结果。该标志主要用于显示、诊断、记录和区分采集段方向。

## 客户端解析建议

```cpp
bool has_scan_direction = (header.meta_flags & 0x2) != 0;
bool reverse_scan = has_scan_direction && header.reverse_scan != 0;
```

推荐客户端界面显示三种状态：

- `未知`：`has_scan_direction == false`
- `正向`：`has_scan_direction == true && reverse_scan == false`
- `反向`：`has_scan_direction == true && reverse_scan == true`

## 文件和回放

原始 raw metadata 的每帧条目新增：

```json
{
  "has_scan_direction": true,
  "reverse_scan": false
}
```

旧 JSON 不包含 `reverse_scan` 时，文件回放会按 `has_scan_direction=true`、`reverse_scan=false` 处理。没有 metadata 的文件源仍按方向未知处理。

光谱投影 TIFF metadata 新增：

```json
{
  "has_scan_direction": true,
  "reverse_scan": true,
  "frame_axis_order": "scan_corrected"
}
```

客户端读取 TIFF 时，如果 `frame_axis_order` 为 `scan_corrected`，说明 frame 轴已经按正向扫描顺序保存。
