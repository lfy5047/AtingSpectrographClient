# 录制数据拉取客户端开发需求

本文档面向客户端开发，说明如何通过服务端新增的 `record.*` 命令拉取历史录制数据并播放/查看。控制命令走现有 TCP 控制协议，文件内容走独立 TCP 文件端口。

完整底层帧格式以 `doc/客户端命令接口.md` 为准。

## 目标

客户端需要支持：

- 查询和设置录制数据保留时间。
- 查询最近的录制文件列表。
- 拉取光谱投影 `.tif` 文件。
- 拉取 raw 数据文件组：`.raw + .json`。
- 使用 TCP 文件传输，不使用 UDP。

## 数据类型

服务端支持两类录制数据：

| 类型 | `type` | 内容 |
|------|--------|------|
| 光谱投影数据 | `tif` | 一个多页 `.tif` 文件 |
| 原始录制数据 | `raw` | 同名 `.raw` 和 `.json` 文件组 |

`record_id` 来自文件名中的纳秒时间戳，例如：

```text
1750972329960213883.raw
1750972329960213883.json
1750972329960213883.tif
```

对应 `record_id` 为：

```text
1750972329960213883
```

## 控制连接

客户端先连接服务端控制 TCP 端口：

```text
control_port = 9000
```

控制命令仍使用现有 RPC 外层响应：

成功：

```json
{"ok": true, "data": {}}
```

失败：

```json
{"ok": false, "code": -3, "msg": "bad params"}
```

## 保留时间

### 查询保留时间

请求：

```json
{"cmd": "record.get_retention", "params": {}}
```

成功响应 `data`：

```json
{
  "retention_seconds": 600
}
```

`retention_seconds = 0` 表示服务端不按时间清理，只按磁盘上限清理。

### 设置保留时间

请求：

```json
{
  "cmd": "record.set_retention",
  "params": {
    "seconds": 600
  }
}
```

成功响应 `data`：

```json
{
  "retention_seconds": 600,
  "raw_estimated_bytes": 23808000000,
  "tif_estimated_bytes": 143994880000
}
```

客户端要求：

- `seconds` 使用非负整数。
- 如果服务端返回失败，不更新本地 UI 中的当前保留时间。
- 设置成功后，服务端会写入 `conf.json`，重启后继续生效。
- 设置成功后，服务端会异步清理超过保留时间的数据。

常见失败：

- 设置时间过长，估算 raw 占用超过 `raw_data_save.max_disk_bytes`。
- 设置时间过长，估算 tif 占用超过 `spectral_projection_data_save.max_disk_bytes`。

## 查询最近文件

### 按最近 N 个记录查询

请求最近 3 个 raw 记录：

```json
{
  "cmd": "record.list_recent",
  "params": {
    "type": "raw",
    "count": 3
  }
}
```

请求最近 5 个 tif 记录：

```json
{
  "cmd": "record.list_recent",
  "params": {
    "type": "tif",
    "count": 5
  }
}
```

### 按最近 N 秒查询

请求最近 60 秒内的 tif：

```json
{
  "cmd": "record.list_recent",
  "params": {
    "type": "tif",
    "last_seconds": 60
  }
}
```

### 同时指定时间和数量

同时指定 `last_seconds` 和 `count` 时，服务端先按时间窗口过滤，再取最新 `count` 个：

```json
{
  "cmd": "record.list_recent",
  "params": {
    "type": "raw",
    "last_seconds": 300,
    "count": 10
  }
}
```

### raw 列表响应

成功响应 `data` 示例：

```json
{
  "type": "raw",
  "items": [
    {
      "record_id": "1750972329960213883",
      "type": "raw",
      "timestamp_ns": 1750972329960213883,
      "raw": {
        "name": "1750972329960213883.raw",
        "size_bytes": 392601600
      },
      "json": {
        "name": "1750972329960213883.json",
        "size_bytes": 4096
      },
      "files": [
        {
          "name": "1750972329960213883.raw",
          "size_bytes": 392601600
        },
        {
          "name": "1750972329960213883.json",
          "size_bytes": 4096
        }
      ]
    }
  ]
}
```

### tif 列表响应

成功响应 `data` 示例：

```json
{
  "type": "tif",
  "items": [
    {
      "record_id": "1750972329960213883",
      "type": "tif",
      "timestamp_ns": 1750972329960213883,
      "tif": {
        "name": "1750972329960213883.tif",
        "size_bytes": 287989760
      },
      "files": [
        {
          "name": "1750972329960213883.tif",
          "size_bytes": 287989760
        }
      ]
    }
  ]
}
```

客户端要求：

- 列表按服务端返回顺序展示即可，当前返回为最新记录在前。
- `record_id` 是后续 `record.fetch` 的输入。
- raw 数据必须按一组 `.raw + .json` 处理。

## 创建文件传输

客户端先通过控制 TCP 创建一次性传输令牌。

请求拉取一个 raw 记录：

```json
{
  "cmd": "record.fetch",
  "params": {
    "type": "raw",
    "items": ["1750972329960213883"]
  }
}
```

请求拉取多个 tif 记录：

```json
{
  "cmd": "record.fetch",
  "params": {
    "type": "tif",
    "items": [
      "1750972329960213883",
      "1750972339960213883"
    ]
  }
}
```

成功响应 `data`：

```json
{
  "transfer_id": "6b8f2d5a-5dd0-44bb-9706-e73a3ec7c61e",
  "file_port": 9001,
  "files": [
    {
      "record_id": "1750972329960213883",
      "name": "1750972329960213883.raw",
      "size_bytes": 392601600
    },
    {
      "record_id": "1750972329960213883",
      "name": "1750972329960213883.json",
      "size_bytes": 4096
    }
  ]
}
```

客户端要求：

- 收到 `transfer_id` 后尽快连接 `file_port`。
- `transfer_id` 默认 30 秒内有效。
- `transfer_id` 只能使用一次。
- 如果文件 TCP 连接失败、断开或超时，需要重新调用 `record.fetch` 获取新的 `transfer_id`。

## 文件 TCP 传输

文件内容不走控制 TCP，而是连接：

```text
host = 服务端 IP
port = record.fetch 返回的 file_port，默认 9001
```

### 握手

连接成功后，客户端立即发送：

| 字段 | 类型 | 说明 |
|------|------|------|
| `json_len` | uint32 little-endian | JSON 字节数 |
| `json` | bytes | `{"transfer_id":"..."}` |

示例 JSON：

```json
{"transfer_id":"6b8f2d5a-5dd0-44bb-9706-e73a3ec7c61e"}
```

如果 `transfer_id` 无效、过期或重复使用，服务端会直接断开文件 TCP 连接，不返回 JSON 错误。

### 接收文件块

握手成功后，服务端连续发送：

```text
FileChunkHeader + filename + payload
```

`FileChunkHeader` 固定 44 字节，所有多字节字段均为 little-endian：

| 偏移 | 类型 | 字段 | 说明 |
|------|------|------|------|
| 0 | uint32 | magic | `0x44465441`，字符串 `"ATFD"` 的 little-endian |
| 4 | uint16 | version | `1` |
| 6 | uint16 | flags | bit0=`LastChunk`，bit1=`LastFile` |
| 8 | uint32 | file_index | 当前文件序号，从 0 开始 |
| 12 | uint32 | file_count | 本次传输文件总数 |
| 16 | uint64 | offset | 当前 payload 在当前文件内的偏移 |
| 24 | uint64 | file_size | 当前文件总字节数 |
| 32 | uint32 | filename_len | 文件名长度 |
| 36 | uint32 | payload_len | payload 长度 |
| 40 | uint32 | reserved | 保留，当前为 0 |

客户端解析流程：

1. 读取 44 字节 `FileChunkHeader`。
2. 校验 `magic == 0x44465441`。
3. 校验 `version == 1`。
4. 读取 `filename_len` 字节，得到文件名。
5. 读取 `payload_len` 字节，追加写入该文件。
6. 使用 `file_index + filename` 区分当前文件。
7. 当 `flags & 0x1` 非 0，表示当前文件最后一块。
8. 当 `flags & 0x2` 非 0，表示本次传输最后一个文件，传输完成。

服务端发送最后一个文件后会关闭文件 TCP 连接。

### 文件完整性校验

客户端至少需要校验：

- 每个文件累计接收字节数等于 `file_size`。
- 文件数量等于 `file_count`。
- `record.fetch` 响应中的 `size_bytes` 与文件 TCP 中的 `file_size` 一致。
- `offset` 连续且不倒退。

如果校验失败：

- 丢弃本次传输产生的不完整文件。
- 重新调用 `record.fetch`。
- 使用新的 `transfer_id` 重新下载。

## raw 数据播放/查看

raw 记录由两个文件组成：

- `.raw`：连续 16bit 原始帧数据。
- `.json`：帧元数据。

客户端必须先读取 `.json`，再解析 `.raw`。

`.json` 关键字段：

| 字段 | 说明 |
|------|------|
| `raw_file` | 对应 `.raw` 文件名 |
| `frame_count` | 帧数 |
| `width` | 图像宽 |
| `height` | 图像高 |
| `frame_bytes` | 单帧字节数 |
| `frames` | 每帧时间戳、帧类型和转镜信息 |

`.raw` 像素格式：

- uint16 little-endian。
- 单帧大小为 `width * height * 2` 字节。
- 帧顺序与 `.json.frames[index]` 对应。

## tif 数据播放/查看

tif 文件是未压缩 16bit 多页灰度 TIFF。

关键含义：

| 维度 | 说明 |
|------|------|
| page | wavelength/x |
| 每页宽 | frame index |
| 每页高 | slice height |
| 像素 | 第 x 页 `(y, frame_index)` 表示对应切片中的 `(y, x)` |

客户端可以使用 TIFF 库读取多页图像，并根据自身 UI 需求做播放、浏览、投影或伪彩显示。

## 推荐客户端流程

1. 连接控制 TCP。
2. 调用 `record.get_retention` 初始化 UI。
3. 用户选择数据类型：`raw` 或 `tif`。
4. 调用 `record.list_recent` 获取最近数据列表。
5. 用户选择一个或多个 `record_id`。
6. 调用 `record.fetch` 获取 `transfer_id` 和 `file_port`。
7. 连接文件 TCP 端口并发送握手。
8. 接收并校验所有文件。
9. raw 按 `.json + .raw` 播放；tif 按多页 TIFF 播放。

## 异常处理要求

客户端需要处理：

- 控制 TCP 命令返回 `ok=false`。
- `record.list_recent` 返回空列表。
- `record.fetch` 返回后超过 30 秒才连接文件端口。
- 文件 TCP 握手后被服务端断开。
- 文件传输中断。
- 文件大小校验失败。
- raw 记录缺少 `.raw` 或 `.json`。
- tif 文件读取失败。

所有文件传输失败场景均按“丢弃本次下载结果，重新 `record.fetch`”处理。

## 验收标准

客户端功能验收至少覆盖：

- 能正确显示当前 `retention_seconds`。
- 能设置合法保留时间，并在 UI 中更新。
- 设置过大的保留时间时能显示服务端错误。
- 能查询最近 N 个 raw 记录。
- 能查询最近 N 个 tif 记录。
- 能下载 raw 文件组，且 `.raw` 和 `.json` 大小与服务端返回一致。
- 能下载 tif 文件，大小与服务端返回一致。
- 同一个 `transfer_id` 第二次使用失败时，客户端能重新获取并下载。
- 文件传输中断后，客户端不会使用不完整文件。
